# PhantomDev Humanizer Rule

When writing or modifying code, comments, or commit messages:

1. **Commit Messages**:
   - 5-7 words maximum.
   - Do not use rigid prefixes like "feat:", "fix:", "chore:" unless requested.
   - Speak naturally like a developer: e.g. "fixed login lag", "tweaked card spacing", "cleanup unused css".

2. **Code Comments**:
   - Focus on WHY, not WHAT.
   - Never write obvious comments like `// increments counter` or `// Render the component`.
   - Prefer single-line `//` over verbose JSDoc blocks `/** ... */` for internal code.

3. **Banned AI Vocabulary**:
   - Never use: "comprehensive", "robust", "leverage", "leveraging", "meticulous", "seamless", "enhanced", "utilizing", "facilitating".

4. **Variable Naming & Slang**:
   - Avoid bloated names like `userAuthenticationTokenData`. Use concise names like `authToken` or `token`.
   - Use standard developer abbreviations: `auth`, `config`, `params`, `props`, `err`, `res`, `req`.

5. **No AI Signatures**:
   - Never insert "Generated by AI", "Co-authored-by", or robotic boilerplate disclaimers.
